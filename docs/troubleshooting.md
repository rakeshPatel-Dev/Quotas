# Troubleshooting

## The app will not start

**`GPU process isn't usable. Goodbye.` followed by a core dump**

Hardware acceleration is disabled but this machine's software fallback is broken.
If you added `app.disableHardwareAcceleration()` to `src/main/index.ts`, remove
it — that call is what causes this. The default (acceleration enabled, with a
failed GPU process falling back to software) works. See the note in
[architecture.md](architecture.md).

**`FATAL:setuid_sandbox_host.cc` or a sandbox error**

The `chrome-sandbox` helper needs to be setuid root:

```bash
sudo chown root:root release/linux-unpacked/chrome-sandbox
sudo chmod 4755 release/linux-unpacked/chrome-sandbox
```

Alternatively run with `--no-sandbox`, which is fine for a local single-user app
but do not ship that.

**`The SUID sandbox helper binary was found, but is not configured correctly`**

Same fix as above.

**`--ozone-platform=wayland is not compatible with Vulkan`**

Cosmetic. Your session is Wayland but `DISPLAY` is also set, so Chromium picks
the Wayland backend and warns about Vulkan, then falls back. The app works. Force
one backend if the noise bothers you:

```bash
./antigravity-quota-tracker --ozone-platform=x11   # or =wayland
```

**`Fontconfig warning: ... generated by a newer version of Fontconfig`**

Also cosmetic. Your system `fc-cache` is newer than the fontconfig library
Electron loads, so the older reader refuses to rewrite newer cache files. Fonts
still resolve, and this app does not depend on it — Inter and JetBrains Mono are
self-hosted. Deleting `~/.cache/fontconfig` only makes the two versions fight
over regenerating it.

**Nothing happens, no window**

Check for a second instance. The app is single-instance by design and a second
launch just focuses the existing window:

```bash
pgrep -x electron
pgrep -af antigravity-quota-tracker
```

## Accounts and sign-in

**`Sign-in expired` on a card**

The refresh token was rejected — after a password change, a revoked grant, or a
long period of inactivity. The app pauses the account automatically, because
retrying a dead token can never succeed.

Click **Re-sign in** on the card. It reopens your browser for a fresh sign-in;
choose the **same** Google account and the card updates in place, keeping its
quota history. Signing in with a *different* account adds a second card instead,
so if you end up with two, remove the one you did not mean to add.

Note that **Refresh** is not a substitute here. It retries the same rejected
token and will simply fail again.

**Sign-in opens a browser but the app never picks it up**

The OAuth flow listens on a loopback port and waits for a redirect. If a
firewall, proxy, or port collision blocks it, the flow times out. The loopback
catcher binds an ephemeral port, so this is usually a proxy intercepting
`localhost` traffic.

**`No account matching "..."`**

The CLI resolves either the full address or a masked one. Use the exact address
the app shows.

**An account I imported shows up twice**

It should not: `import` and the OAuth flow derive the same id from the
lowercased address. If you genuinely have two, they are different Google
accounts. Remove the duplicate you do not want.

## Quota data looks wrong

**Everything says `unmetered`**

Usually correct, not a bug. Google provisions quota meters per account, and only
some accounts get a `remainingFraction`. Accounts that have never run a model
return no pools at all. See [api-findings.md](api-findings.md).

To find out what Google actually sent:

```bash
npx tsx scripts/debugQuotaShape.ts
```

**Everything suddenly says `unmetered` or `Failed` after working before**

Almost certainly an upstream change. The quota endpoint is internal and
undocumented. Run the debug script above and compare against `FINDINGS.md`.

**Pools merge several models into one row**

That is the intended behaviour — models share meters. See
[api-findings.md](api-findings.md).

**Countsdowns disagree with Google's own UI**

Countdowns come from the `resetTime` the API returns, computed against your
local clock. A skewed system clock will show wrong countdowns. Check with
`timedatectl`.

## Data and storage

**`Primary accounts file was unreadable; recovered N accounts from backup`**

`accounts.json` could not be parsed, so the app fell back to
`accounts.json.bak`. Usually a crash during a write. The recovered copy may be
one write behind.

**Account data is not where I expect**

```bash
npm run dev -- help   # prints the data dir
```

Or:

```bash
echo "${ANTIGRAVITY_TRACKER_DATA_DIR:-$HOME/.antigravity-quota-tracker}"
```

The packaged app uses the same directory as `npm run app`, and both share data
with the CLI. Upgrading the app never touches it.

**I want to move my accounts to another machine**

Copy the whole `~/.antigravity-quota-tracker/` directory, including `dev.key` if
it exists. Without `dev.key`, any value sealed with the keyfile backend cannot be
read.

**Changes made by the CLI disappeared when I opened the app**

Do not run the CLI while the app is open. Both hold independent in-memory copies
and write the same file. Close the app first.

## Build problems

**`npm run dist` fails on the `.deb` step with `libcrypt.so.1`**

electron-builder's bundled Ruby needs a library many current distros no longer
ship. This does not affect the AppImage. Use:

```bash
npm run dist:appimage
```

**`npm install` warns that install scripts are blocked**

npm 11+ blocks lifecycle scripts by default. `electron-builder` needs its
binaries. Review and approve them:

```bash
npm install-scripts ls
npm install-scripts approve <pkg>
```

If `app-builder-bin` or `7zip-bin` are missing, that is the cause.

**Electron quits instantly with no output**

Usually the single-instance lock: another instance is already running, and this
one exits immediately by design. Confirm with `pgrep -x electron`.

**The packaged app shows a blank window**

A blank window usually means the renderer failed to load its assets from inside
the asar. Check `build.base` in `vite.config.ts` is `'./'` — an absolute `/`
base resolves to the filesystem root rather than inside the archive.

**Placeholder metadata in the package**

`author.email`, `homepage` and `build.linux.maintainer` in `package.json` are
placeholders. They exist because electron-builder will not build a `.deb`
without a maintainer address. Replace them before distributing. See
[building.md](building.md).

## Reporting a bug

Include, with credentials redacted:

- Output of `npm run dev -- accounts`
- Output of `npx tsx scripts/debugQuotaShape.ts`
- Anything the terminal that launched the app logged, including `[store]` lines
- Your Electron version (`npx electron --version`) and distro

Never paste `accounts.json` or `dev.key`. Both are gitignored for a reason.
